# Feature Specification: QANOW 질문·답변 게시판

**Feature Branch**: `001-qanow-qa-board`

**Created**: 2026-08-20

**Status**: Draft

**Input**: User description: "QANOW라는 회원 질문·관리자 답변 게시판을 만들고 싶다. 사용자는 질문을 남기고 자신의 질문·답변 상태를 볼 수 있어야 하며, 관리자는 답변이 필요한 질문을 찾아 답변한다. 메인 페이지, 질문 리스트 페이지, 질문 페이지 3개 핵심 화면. 비회원/회원/관리자 3개 역할, 권한 규칙, 입력 규칙(제목 1~100자, 내용/답변 1~5000자), 상태(로딩/빈 목록/오류/권한 없음/저장 중), MVP 제외 항목(파일 첨부, 댓글, 검색, 페이지네이션, 소셜 로그인, 통계 대시보드) 명시."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 질문을 등록하고 처리 상태를 추적한다 (Priority: P1)

회원은 궁금한 점을 질문으로 남기고, 이후 자신의 질문이 답변 대기 중인지 답변 완료
상태인지 확인할 수 있다.

**Why this priority**: 질문 등록과 상태 확인은 서비스의 핵심 가치 제안이다. 이것이
동작하지 않으면 게시판이 존재할 이유가 없다.

**Independent Test**: 회원으로 로그인 후 질문을 작성하고, 질문 리스트 페이지에서
방금 작성한 질문이 "답변 대기" 상태로 표시되는지 확인하는 것만으로 독립적으로
테스트하고 가치를 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 질문 페이지에 있다, **When** 제목과 내용을 규칙에 맞게
   입력하고 등록한다, **Then** 질문이 저장되고 질문 리스트에서 "답변 대기" 상태로
   나타난다.
2. **Given** 회원이 이전에 등록한 질문이 아직 답변되지 않았다, **When** 질문 상세
   페이지를 연다, **Then** 질문 내용과 "답변 대기" 상태, 수정·삭제 버튼이 보인다.
3. **Given** 관리자가 회원의 질문에 답변을 작성했다, **When** 회원이 질문 상세
   페이지를 연다, **Then** 질문과 함께 관리자 답변이 표시되고 상태는 "답변 완료"로
   바뀐다.

---

### User Story 2 - 관리자가 답변 대기 질문을 찾아 답변한다 (Priority: P1)

관리자는 전체 질문 목록에서 답변이 필요한 질문을 식별하고, 질문을 열어 답변을
작성하거나 이미 작성한 답변을 수정한다.

**Why this priority**: 답변 제공이 이루어지지 않으면 회원의 질문이 방치되어 서비스
가치가 성립하지 않는다. User Story 1과 함께 MVP의 필수 왕복 흐름을 구성한다.

**Independent Test**: 관리자로 로그인해 전체 질문 목록에서 답변 대기 질문을 찾아
답변을 작성하고, 저장 후 해당 질문의 상태가 "답변 완료"로 바뀌는 것을 확인하는
것만으로 독립적으로 테스트할 수 있다.

**Acceptance Scenarios**:

1. **Given** 관리자가 전체 질문 목록 페이지에 있다, **When** 목록을 확인한다,
   **Then** 모든 회원의 질문이 각각의 답변 대기/답변 완료 상태와 함께 표시된다.
2. **Given** 관리자가 답변 대기 질문의 상세 페이지를 열었다, **When** 답변을
   규칙에 맞게 작성하고 등록한다, **Then** 답변이 저장되고 질문 상태가
   "답변 완료"로 바뀐다.
3. **Given** 관리자가 이미 답변한 질문의 상세 페이지를 열었다, **When** 답변
   내용을 수정하고 저장한다, **Then** 수정된 답변이 반영된다.

---

### User Story 3 - 비회원이 서비스를 이해하고 회원가입·로그인으로 이어진다 (Priority: P2)

비회원은 메인 페이지에서 QANOW가 무엇을 하는 서비스인지, 질문을 남기면 어떤 흐름을
거쳐 답변을 받는지 이해하고, 질문 작성을 시도하면 로그인 필요 안내를 받는다.

**Why this priority**: 신규 사용자의 첫 진입점이며 회원 전환의 시작점이지만, 이미
회원가입을 마친 사용자에게는 매번 필요하지 않으므로 P1보다 낮다.

**Independent Test**: 비로그인 상태로 메인 페이지에 접속해 서비스 소개와 이용
흐름을 확인하고, 질문 작성 CTA를 클릭했을 때 로그인 안내로 이어지는 것을 확인하는
것만으로 독립적으로 테스트할 수 있다.

**Acceptance Scenarios**:

1. **Given** 비회원이 메인 페이지에 접속했다, **When** 페이지를 확인한다,
   **Then** 서비스 소개와 "질문 작성 → 관리자 확인 → 답변 확인" 이용 흐름, 질문
   작성 CTA가 보인다.
2. **Given** 비회원이 메인 페이지의 질문 작성 CTA를 클릭했다, **When** 질문 작성
   화면으로 이동을 시도한다, **Then** 로그인 안내가 표시되고 질문 작성 화면에
   접근하지 못한다.
3. **Given** 비회원이 질문 리스트 페이지나 질문 상세 페이지 URL에 직접 접근한다,
   **When** 페이지가 로드된다, **Then** 로그인 안내가 표시된다.

---

### User Story 4 - 회원이 답변 전 자신의 질문을 수정·삭제한다 (Priority: P3)

회원은 아직 관리자 답변이 달리지 않은 자신의 질문을 다시 열어 내용을 수정하거나
삭제할 수 있다.

**Why this priority**: 핵심 왕복 흐름(P1, P1) 이후에 필요한 보조 기능으로, 없어도
질문·답변의 기본 가치는 성립하지만 사용자 편의를 높인다.

**Independent Test**: 답변 대기 중인 자신의 질문을 열어 내용을 수정 저장하거나
삭제하고, 목록에서 변경 또는 삭제가 반영되는 것을 확인하는 것만으로 독립적으로
테스트할 수 있다.

**Acceptance Scenarios**:

1. **Given** 회원의 질문이 아직 답변되지 않았다, **When** 질문 상세 페이지에서
   제목/내용을 수정하고 저장한다, **Then** 변경된 내용이 저장되고 상세 페이지에
   반영된다.
2. **Given** 회원의 질문이 아직 답변되지 않았다, **When** 삭제를 실행하고 확인한다,
   **Then** 질문이 삭제되고 질문 리스트에서 더 이상 보이지 않는다.
3. **Given** 관리자가 이미 답변한 회원의 질문이다, **When** 회원이 질문 상세
   페이지를 연다, **Then** 수정·삭제 버튼이 보이지 않거나 비활성화되어 있다.

---

### Edge Cases

- 회원이 다른 회원 소유 질문의 상세 URL에 직접 접근하면 어떻게 되는가? → 권한 없음
  상태를 표시하고 내용은 노출하지 않는다.
- 관리자가 답변을 저장하는 도중 네트워크 오류가 발생하면 어떻게 되는가? → 오류
  상태를 표시하고 회원의 질문 상태는 "답변 완료"로 바뀌지 않은 채 유지한다.
- 회원이 질문 제목/내용을 공백만으로 채워 제출하면 어떻게 되는가? → 저장을
  거부하고 유효성 오류를 표시한다(공백 제거 후 최소 길이 미달).
- 회원이 질문을 수정하는 사이 관리자가 먼저 답변을 등록하면 어떻게 되는가? →
  저장 시점에 답변 완료 상태를 재확인하여 저장을 거부하고, "이미 답변된 질문은
  수정할 수 없습니다" 오류를 표시한다.
- 회원이 아직 질문을 하나도 등록하지 않았다면 질문 리스트 페이지는 어떻게
  보이는가? → 빈 목록 상태와 함께 질문 작성 CTA를 표시한다.
- 관리자가 답변 대기 질문이 하나도 없는 상태로 전체 목록을 열면 어떻게 되는가? →
  빈 목록 상태를 표시한다.
- 로그인 세션이 만료된 상태에서 회원이 저장을 시도하면 어떻게 되는가? → 저장을
  거부하고 로그인 안내로 전환한다.

## Requirements *(mandatory)*

### Functional Requirements

**공통 / 계정**

- **FR-001**: 시스템은 비회원이 이메일과 비밀번호로 회원가입할 수 있게 해야 한다.
- **FR-002**: 시스템은 회원과 관리자가 로그인하고 로그아웃할 수 있게 해야 한다.
- **FR-003**: 시스템은 각 계정이 회원 또는 관리자 중 하나의 역할을 가지도록
  구분해야 한다.

**메인 페이지**

- **FR-004**: 시스템은 메인 페이지에서 서비스 소개, 질문 작성 CTA, "질문 작성 →
  관리자 확인 → 답변 확인" 이용 흐름을 비회원을 포함한 모든 방문자에게 보여줘야
  한다.
- **FR-005**: 시스템은 비회원이 메인 페이지의 질문 작성 CTA를 실행하면 모달/팝업
  형태의 로그인 폼을 표시하고 질문 작성 화면 진입을 막아야 한다. 로그인 성공 시
  모달을 종료하고 질문 작성 페이지로 진입할 수 있다.

**질문 작성·조회**

- **FR-006**: 시스템은 로그인한 회원이 질문 제목과 내용을 입력해 질문을 등록할 수
  있게 해야 한다.
- **FR-007**: 시스템은 질문 제목이 공백 제거 후 1자 이상 100자 이하가 아니면 저장을
  거부하고 오류를 표시해야 한다.
- **FR-008**: 시스템은 질문 내용이 공백 제거 후 1자 이상 5000자 이하가 아니면
  저장을 거부하고 오류를 표시해야 한다.
- **FR-009**: 시스템은 새로 등록된 질문의 상태를 "답변 대기"로 초기화해야 한다.
- **FR-010**: 시스템은 회원이 질문 리스트 페이지에서 자신이 작성한 질문을 상태
  (답변 대기/답변 완료)로 필터링하여 조회할 수 있게 해야 한다. 필터 옵션은 '모두',
  '답변 대기', '답변 완료' 세 가지를 제공한다.
- **FR-011**: 시스템은 관리자가 질문 리스트 페이지에서 모든 회원의 질문을 상태
  (답변 대기/답변 완료)로 필터링하여 조회할 수 있게 해야 한다. 필터 옵션은 '모두',
  '답변 대기', '답변 완료' 세 가지를 제공한다.
- **FR-012**: 시스템은 회원과 관리자가 질문 상세 페이지에서 질문 내용과 등록된
  답변(있는 경우)을 확인할 수 있게 해야 한다.

**질문 수정·삭제**

- **FR-013**: 시스템은 회원이 아직 답변되지 않은 자신의 질문의 제목과 내용을
  수정할 수 있게 해야 하며, 수정 시에도 FR-007·FR-008의 길이 규칙을 적용해야 한다.
- **FR-014**: 시스템은 회원이 아직 답변되지 않은 자신의 질문을 삭제할 수 있게
  해야 한다.
- **FR-015**: 시스템은 관리자가 답변을 등록한 이후에는 해당 질문에 대한 회원의
  수정·삭제 요청을 데이터 계층에서 거부해야 한다.

**답변**

- **FR-016**: 시스템은 관리자가 답변 대기 질문에 답변을 작성해 등록할 수 있게
  해야 한다.
- **FR-017**: 시스템은 답변이 공백 제거 후 1자 이상 5000자 이하가 아니면 저장을
  거부하고 오류를 표시해야 한다.
- **FR-018**: 시스템은 답변이 등록되면 해당 질문의 상태를 "답변 완료"로 변경해야
  한다.
- **FR-019**: 시스템은 관리자가 이미 등록된 답변의 내용을 수정할 수 있게 해야
  하며, 수정 시에도 FR-017의 길이 규칙을 동일하게 적용해야 한다.
- **FR-020**: 시스템은 회원이 답변을 작성하거나 수정하지 못하도록 데이터 계층에서
  차단해야 한다.

**권한**

- **FR-021**: 시스템은 회원이 다른 회원이 작성한 질문을 조회·수정·삭제하지 못하도록
  데이터 계층에서 차단한다. 권한 없는 URL 직접 접근 시, 현재 페이지에서 "이 질문에
  접근할 권한이 없습니다" 메시지와 목록으로 돌아가기 버튼을 표시하는 권한 없음
  상태를 표시해야 한다.
- **FR-022**: 시스템은 비회원이 질문 작성, 질문 리스트, 질문 상세 등 보호된
  화면에 접근하면 로그인 안내를 표시해야 한다.

**상태 표시**

- **FR-023**: 시스템은 목록·상세·저장 동작에서 로딩, 빈 목록, 오류, 권한 없음,
  저장 중 상태를 사용자에게 명확히 구분해 표시해야 한다.
- **FR-024**: 시스템은 빈 목록 상태에서 역할별 행동을 안내해야 한다. 회원은 "아직
  질문이 없습니다" 메시지와 함께 질문 작성 CTA를 표시하고, 관리자는 "답변 대기
  질문이 없습니다" 메시지와 함께 필터 변경 버튼을 표시한다.

### Key Entities

- **회원(Member)**: 질문을 등록·조회·수정·삭제하는 계정. 이메일, 비밀번호(저장
  형태는 구현 단계에서 결정), 역할 구분자를 가진다. 질문 목록과 상세 페이지에서
  질문 작성자는 이메일로 표시된다.
- **관리자(Admin)**: 모든 질문을 조회하고 답변을 작성·수정하는 계정. 회원과 동일한
  계정 구조에 역할만 다르다.
- **질문(Question)**: 회원이 등록하는 문의. 제목, 내용, 작성자(회원), 상태
  (답변 대기/답변 완료), 등록 시각, 수정 시각을 가진다.
- **답변(Answer)**: 관리자가 특정 질문에 대해 등록하는 응답. 내용, 작성 관리자,
  등록 시각, 수정 시각을 가지며 하나의 질문에 최대 하나만 존재한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 방문자가 메인 페이지만 보고도 "질문을 남기면 관리자가 답변한다"는
  서비스 흐름을 별도 설명 없이 이해할 수 있다(사용자 테스트에서 90% 이상이 이용
  흐름을 정확히 설명함).
- **SC-002**: 회원은 회원가입 후 5분 이내에 첫 질문 등록을 완료할 수 있다.
- **SC-003**: 관리자는 답변 대기 질문을 목록에서 열람한 뒤 3분 이내에 답변 등록을
  완료할 수 있다.
- **SC-004**: 회원이 자신의 질문 상태(답변 대기/답변 완료)를 확인하는 데 목록
  페이지 진입 후 추가 조작 없이 즉시 확인 가능하다.
- **SC-005**: 다른 회원의 질문에 대한 무단 조회·수정·삭제 시도는 100% 차단되며,
  이는 UI 제한 우회(직접 접근) 시에도 동일하게 적용된다.
- **SC-006**: 질문·답변 등록 시도 중 형식에 맞지 않는 입력(길이 위반, 공백만
  입력)은 100% 저장 거부되고 오류 상태로 안내된다.
- **SC-007**: 핵심 시나리오(질문 등록, 답변 확인, 답변 작성)는 데스크톱과 모바일
  화면 모두에서 처음부터 끝까지 완료 가능하다.

## Assumptions

- 회원가입은 이메일과 비밀번호 기반이며, 소셜 로그인은 MVP 범위 밖이다(사용자 요청
  명시).
- 관리자 계정은 별도의 관리자 전용 가입 절차 없이 사전에 부여된다고 가정한다(관리자
  가입 흐름은 요청에 포함되지 않음).
- 비밀번호 재설정, 이메일 인증 등 부가 계정 기능은 이번 MVP 범위에 포함하지 않는다.
- 하나의 질문에는 하나의 답변만 존재하며, 답변은 등록 후 관리자가 수정할 수 있지만
  회원의 재질문/추가 질문(스레드형 대화)은 이번 범위에 포함하지 않는다.
- 파일 첨부, 댓글, 검색, 페이지네이션, 소셜 로그인, 통계 대시보드는 사용자 요청에
  따라 MVP에서 제외한다.
- 질문 리스트는 페이지네이션이 없으므로 등록된 전체 질문(회원은 본인 것, 관리자는
  전체)을 한 화면에 표시한다고 가정한다.

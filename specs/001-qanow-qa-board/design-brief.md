# QANOW 디자인 브리프

**Status**: For Claude Design System  
**Project**: QANOW 질의응답 게시판  
**Version**: 1.0  
**Created**: 2026-08-20

---

## 1. 프로젝트와 사용자 요약

**프로젝트**: QANOW는 회원이 질문을 남기면 관리자가 답변하는 신뢰 기반 Q&A 플랫폼입니다.

**사용자 역할**:
- **회원**: 질문 작성, 자신의 질문과 답변 상태 확인, 답변 전 질문 수정/삭제
- **관리자**: 전체 질문 조회, 답변 대기 질문 우선 처리, 답변 작성·수정
- **비회원**: 메인 페이지에서 서비스 이해, 회원가입 유도

**핵심 가치**: 명확한 질문·답변 흐름, 빠른 응답 시간, 신뢰감 있는 정보 제공

---

## 2. 디자인 목표

1. **신뢰감과 정보성**: 질의응답 서비스의 정당성을 첫 인상에 전달
2. **효율성**: 내부 사용자(회원, 관리자)의 작업 시간 최소화
3. **명확한 상태 표시**: 질문의 진행 상태(대기/완료)를 한눈에 파악
4. **모바일 우선**: 모든 핵심 시나리오를 모바일에서 완료 가능하도록 설계
5. **접근성**: WCAG 2.2 AA 준수, 모션 감소 지원, 색상+텍스트 병기
6. **성능**: 시각 효과가 로딩 속도와 인터랙션을 해치지 않음

---

## 3. 브랜드 키워드

- **신뢰** — 명확한 권한 분리, 투명한 상태 추적
- **효율** — 불필요한 단계 제거, 직관적 네비게이션
- **현대성** — 미니멀한 라인, 정돈된 배치, 모던 색상
- **접근성** — 모든 디바이스와 능력의 사용자를 배려

## 4. 핵심 화면 3개의 목적

### 메인 페이지 (Landing Page)
**목적**: 비회원에게 QANOW의 목적과 이용 흐름을 90초 내에 이해시키고 회원가입으로 유도  
**주요 요소**:
- 서비스 소개 문구
- "질문 작성 → 관리자 확인 → 답변 확인" 플로우 시각화
- 강한 시각 첫인상 (오로라 그라데이션, 플로팅 카드)
- 회원가입/로그인 CTA

### 질문 리스트 페이지 (Question List)
**목적**: 회원은 자신의 질문을, 관리자는 전체 질문을 상태별로 필터링하며 효율적으로 관리  
**주요 요소**:
- 상태별 필터 탭 (모두/답변 대기/답변 완료)
- 질문 카드 목록 (제목, 상태, 작성자, 작성 시간)
- 질문 작성 CTA (회원) / 필터 변경 버튼 (관리자)
- 빈 목록 상태와 안내 메시지

### 질문 페이지 (Question Create / Detail)
**목적**: 질문 작성, 상세 조회, 답변 확인, 수정/삭제를 단일 인터페이스로 처리  
**주요 요소**:
- 질문 작성 폼 (제목, 내용 입력 필드)
- 질문 상세 정보 (제목, 내용, 작성자, 상태)
- 관리자 답변 영역 (작성/수정 폼)
- 수정/삭제 버튼 (권한에 따라 표시/숨김)
- 목록으로 돌아가기 버튼

## 5. 화면별 정보 우선순위

### 메인 페이지
1. **서비스명 + 한줄 소개** — 상단 중앙 (가장 강조)
2. **이용 흐름 시각화** — 중앙 영역 (큰 아이콘/화살표/카드)
3. **회원가입 CTA 버튼** — 우측 상단 / 중앙 하단
4. **추가 설명 텍스트** — 보조 정보 (선택적 스크롤)

### 질문 리스트 페이지
1. **상태별 필터 탭** — 상단 (즉시 접근)
2. **질문 카드 목록** — 전체 영역 (제목/상태/작성자가 한눈에)
3. **빈 목록 메시지** — 중앙 (비어있을 때만)
4. **질문 작성 CTA** — 상단 우측 또는 하단 부동

### 질문 페이지
1. **질문 제목** — 상단 (가장 먼저 눈에 띔)
2. **작성자 + 상태 뱃지** — 제목 아래
3. **질문 내용** — 중앙 (넉넉한 여백)
4. **관리자 답변** — 질문 아래 (명확한 구분선 또는 카드)
5. **수정/삭제 버튼** — 우측 상단 또는 하단

- [ ] 질문 제목 (큰 폰트, 강조)

- [ ] 작성자 (이메일) + 작성 시간

- [ ] 수정 버튼 (답변 전일 때만) / 삭제 버튼 (답변 전일 때만)
- [ ] 목록으로 돌아가기 버튼

### 질문 페이지 (상세 모드 — 관리자)
- [ ] 질문 제목 + 상태 뱃지
- [ ] 작성자 (이메일) + 작성 시간
- [ ] 질문 내용

## 8. 회원과 관리자 상태 차이

### 질문 리스트
**회원**:
- "내 질문" 제목
- 자신이 작성한 질문만 표시
- 필터: 모두 / 답변 대기 / 답변 완료

**관리자**:
- "전체 질문" 제목
- 모든 회원의 질문 표시 (작성자 표시)
- 필터: 모두 / 답변 대기 / 답변 완료

### 질문 상세
**회원** (답변 전):
- 수정 버튼 표시
- 삭제 버튼 표시

**회원** (답변 후):
- 수정 버튼 없음 / 비활성화
- 삭제 버튼 없음 / 비활성화

**관리자** (답변 전):
- 답변 작성 폼 표시
- 저장 버튼

**관리자** (답변 후):
- 기존 답변 수정 폼 표시
- 저장 버튼

## 9. 페이지 간 이동 구조

```
메인 페이지
├─ 비회원 "질문 하기" 클릭
│  └─ 로그인 모달 표시
│     ├─ 로그인 성공 → 질문 작성 페이지
│     └─ 회원가입 링크 → (MVP 제외)
│
├─ 회원 "질문 하기" 클릭
│  └─ 질문 작성 페이지
│     ├─ 저장 → 질문 리스트 페이지
│     └─ 취소 → 질문 리스트 페이지
│
├─ 헤더 로그인 링크
│  └─ 로그인 모달
│
└─ 헤더 QANOW 로고
   └─ 질문 리스트 페이지

질문 리스트 페이지
├─ 필터 탭 선택 → 같은 페이지 내 필터 적용
├─ 질문 카드 클릭 → 질문 상세 페이지
├─ "새 질문 작성" 버튼 → 질문 작성 페이지
└─ 로그아웃 → 메인 페이지

질문 상세 페이지 (작성 모드)
├─ 저장 → 질문 리스트 페이지 (새 질문 추가)
└─ 취소 → 질문 리스트 페이지

질문 상세 페이지 (상세 모드)
├─ 수정 버튼 → 같은 페이지의 수정 모드로 전환
├─ 저장 (수정 후) → 상세 모드로 전환
├─ 삭제 버튼 → 삭제 확인 → 질문 리스트 페이지
└─ 목록 버튼 → 질문 리스트 페이지
```

## 10. 콘텐츠 예시 문구

### 메인 페이지
- **서비스명**: "QANOW"
- **한줄 설명**: "신뢰할 수 있는 Q&A 플랫폼. 질문하면 관리자가 답변합니다."
- **플로우 설명**:
  - Step 1: "질문 작성" — "궁금한 점을 자유롭게 질문하세요"
  - Step 2: "관리자 확인" — "관리자가 신속하게 검토합니다"
  - Step 3: "답변 확인" — "명확한 답변을 받으세요"
- **CTA 버튼**: "지금 질문하기" / "질문 시작"

### 질문 리스트 페이지
- **빈 목록 (회원)**: "아직 질문이 없습니다. 첫 질문을 남겨보세요!"
- **빈 목록 (관리자, 답변 대기 필터)**: "답변 대기 중인 질문이 없습니다."
- **필터 탭**: 모두 / 답변 대기 / 답변 완료
- **버튼**: "+ 새 질문 작성"

### 질문 페이지 (작성 모드)
- **페이지 제목**: "새 질문 작성"
- **제목 필드 라벨**: "질문 제목" (1~100자)
- **내용 필드 라벨**: "질문 내용" (1~5000자)
- **플레이스홀더**: 
  - 제목: "질문을 간결하게 입력하세요"
  - 내용: "궁금한 점을 자세히 설명해주세요"
- **버튼**: "저장" / "취소"

### 질문 페이지 (상세 모드 — 회원)
- **상태 뱃지**:
  - 답변 대기: "답변 대기 중" (노란색)
  - 답변 완료: "답변 완료" (초록색)
- **버튼**:
  - 답변 전: "수정" / "삭제"
  - 답변 후: 버튼 없음 / 비활성화

### 질문 페이지 (상세 모드 — 관리자)
- **답변 폼 라벨**: "관리자 답변" (1~5000자)
- **플레이스홀더**: "명확하고 친절한 답변을 작성해주세요"
- **버튼**: "답변 저장" / "취소"

### 권한 없음 상태
- **메시지**: "이 질문에 접근할 권한이 없습니다."
- **버튼**: "목록으로 돌아가기"

### 로딩 상태
- **메시지**: "로딩 중입니다…" (또는 스켈레톤 UI)

### 오류 상태
- **메시지**: "문제가 발생했습니다. 나중에 다시 시도해주세요." (또는 구체적 오류 설명)
- **버튼**: "다시 시도" / "목록으로 돌아가기"

## 11. 색상 역할

### 팔레트
| 역할 | 색상명 | 값 | 사용처 |
|------|--------|-----|-------|
| Primary | Deep Navy | #1a2840 | 헤더, 제목, 강조 텍스트 |
| Accent | Vibrant Blue | #2563eb | 버튼, 링크, 강조 요소 |
| Accent | Violet | #7c3aed | 보조 CTA, 강조 포인트 |
| Background | Light Surface | #f9fafb | 내부 페이지 배경 |
| Background | Lighter Surface | #ffffff | 카드, 입력 필드 배경 |
| State - Waiting | Amber | #f59e0b | "답변 대기" 뱃지 |
| State - Done | Emerald | #10b981 | "답변 완료" 뱃지 |
| State - Error | Red | #ef4444 | 오류 메시지, 삭제 버튼 |
| Neutral | Gray | #6b7280 ~ #d1d5db | 보조 텍스트, 경계선 |

### 메인 페이지 그라데이션
- **Hero 배경**: Deep Navy → Vibrant Blue → Violet (오로라 효과, 좌상향 → 우하향)
- **플로팅 카드 배경**: 흰색 또는 반투명 (Glassmorphism 가볍게)

### 내부 페이지
- **헤더/내비게이션**: Deep Navy (고정)
- **배경**: Light Surface (#f9fafb)
- **카드/입력**: 흰색 (#ffffff)
- **버튼**: Vibrant Blue (Primary CTA) / Gray (Secondary CTA)

### 상태 색상
- **필터 활성**: Vibrant Blue (탭 밑줄/배경)
- **필터 비활성**: Gray
- **호버**: 색상 밝기 +10%
- **활성화 불가**: Gray + 50% 투명도

## 12. 타이포그래피 방향

### 폰트 선택
- **제목**: 명확하고 모던한 산세리프 (예: Inter, Poppins, Pretendard)
- **본문**: 가독성 높은 산세리프 (예: Inter, -apple-system, Segoe UI)

### 계층 구조

## 15. 메인 페이지 시각 효과 규칙

### Hero 배경
- **그라데이션**: Deep Navy (#1a2840) → Vibrant Blue (#2563eb) → Violet (#7c3aed)
- **방향**: 좌상향(45°) → 우하향(225°)
- **속도**: 느린 애니메이션 (6초 사이클, loop) — prefers-reduced-motion에서는 정적 상태로 표시
- **효과 이름**: "Aurora Gradient"

### 미세한 그리드 오버레이
- **패턴**: 60px × 60px 격자 (또는 80px)
- **색상**: 흰색 1px 선, 5% 투명도
- **목적**: 배경에 미세한 질감 추가, 모던한 느낌
- **성능**: CSS로 구현 (이미지 X, background-image: linear-gradient)

### 플로팅 카드
- **애니메이션**: 부드러운 위아래 움직임 (2초 사이클)
- **움직임 범위**: ±4px (수직)
- **지연**: 각 카드마다 0.5초씩 오프셋
- **효과**: 생동감 있지만 방해하지 않는 수준

### 타이포그래피 애니메이션
- **텍스트 페이드인**: 페이지 로드 시 각 요소가 순차적으로 나타남 (0.3~0.5초)
- **지연**: 1단계(0ms) → 2단계(200ms) → 3단계(400ms)
- **트랜지션**: ease-out

### 성능 고려사항
- **렌더링**: GPU 가속 (transform, opacity 사용)
- **프레임 레이트**: 60fps 유지
- **로딩 블록**: 애니메이션이 콘텐츠 로딩을 지연시키지 않음
- **전력 효율**: prefers-reduced-motion에서 모든 애니메이션 비활성화

### 제약 사항
- ❌ 과도한 Glassmorphism (반투명 배경 위에 흐림 효과) 금지
- ❌ 과도하게 둥근 모서리 (border-radius > 12px) 금지
- ❌ 낙서체, 필기체 폰트 금지
- ❌ 밝은 네온 색상 금지 (신뢰감 저해)
- ❌ 회전하는 로딩 스피너만으로 상태 표시 (텍스트 필수)

## 18. 접근성과 모션 감소 기준

### 색상 대비
- **일반 텍스트**: 최소 4.5:1 (WCAG AA, Small text)
- **큰 텍스트** (18px 이상): 최소 3:1 (WCAG AA)
- **UI 컴포넌트** (경계선): 최소 3:1
- **상태 색상**: 색상만으로 구분하지 않음 (텍스트 라벨 필수)

### 키보드 네비게이션
- **Tab 순서**: 좌→우, 상→하 (자연스럽게)
- **포커스 인디케이터**: 
  - 링크/버튼: 2px 아웃라인 (Vibrant Blue #2563eb)
  - 입력 필드: 2px 경계 (Vibrant Blue)
  - 가시성: 배경색과 대비 최소 3:1
- **포커스 제거 금지**: outline: none 사용 X (항상 outline 표시)
- **Skip Link**: "콘텐츠로 건너뛰기" (페이지 시작 부분)

### 스크린 리더 지원 (Semantic HTML)
- **페이지 구조**: `<main>`, `<section>`, `<article>` 사용
- **제목 계층**: H1 (한 번만) → H2 → H3 (논리적 순서)
- **폼 레이블**: `<label for="input-id">` 명시적 연결
- **버튼 텍스트**: 명확하고 행동 기반 ("저장", "삭제", "더보기" 등)
- **아이콘 버튼**: `aria-label` 필수 (텍스트 라벨이 없으면)
- **이미지**: `alt` 텍스트 필수 (이미지가 의미 있으면) 또는 `alt=""` (장식용)
- **상태 표시**: `aria-live="polite"` (로딩/오류 메시지)
- **모달**: `role="dialog"`, `aria-modal="true"`, 포커스 트래핑

### 모션 감소 (prefers-reduced-motion)
**적용 대상**:
- 그라데이션 애니메이션 (정적으로 표시)
- 플로팅 카드 애니메이션 (비활성화)
- 페이드인/아웃 트랜지션 (즉시 표시)
- 로딩 스피너 회전 (정지 또는 펄스 애니메이션)

**프리셋 값**: `prefers-reduced-motion: reduce` 사용자는 모든 애니메이션이 비활성화됨

## 19. 만들지 말아야 할 디자인

### ❌ 피해야 할 패턴

1. **과도한 Glassmorphism** — 반투명 배경 + 흐림 효과 남용
2. **과도하게 둥근 카드/버튼** — border-radius > 12px
3. **밝은 네온 색상** — 신뢰감 저해, 눈 피로
4. **흔한 AI 랜딩 페이지 클리셰** — 우주 배경, 별 입자, 에일리언 느낌의 색상
5. **너무 많은 옵션/CTA** — 한 화면에 5개 이상 버튼
6. **텍스트만의 설명** — 플로우는 텍스트 + 아이콘 필요
7. **색상만으로 상태 구분** — 색상 + 텍스트 라벨 필수
8. **반응형 미지원** — 모바일에서 레이아웃 깨짐
9. **로딩 상태 없음** — 저장 중인데 피드백 없음
10. **회전 로고 또는 과도한 애니메이션** — Hero에서 회전하는 요소들

## 20. Claude Design 시안 평가 기준

### 승인 체크리스트

#### 시각 설계
- [ ] 색상이 요청된 팔레트 (Deep Navy, Vibrant Blue, Violet)를 따르는가?
- [ ] 메인 페이지 Hero가 오로라 그라데이션 + 미세한 그리드 + 플로팅 카드를 포함하는가?
- [ ] 내부 페이지가 밝고 정돈된 Surface(#f9fafb) 배경을 사용하는가?
- [ ] 과도한 Glassmorphism이나 둥근 모서리(>12px)가 없는가?

#### 정보 계층
- [ ] 각 페이지의 주요 정보가 명확한 계층으로 표시되는가?
- [ ] 상태 뱃지(답변 대기/완료)가 명시적으로 표시되는가?

#### 컴포넌트
- [ ] 버튼이 44px 높이 (터치 친화적)를 따르는가?
- [ ] 입력 필드가 44px 높이이고 충분한 패딩을 가지는가?
- [ ] 배지(상태 표시)가 색상 + 텍스트를 모두 표시하는가?

#### 반응형
- [ ] 메인 페이지가 모바일(375px)에서 깨지지 않는가?
- [ ] 입력 필드가 모바일에서 100% 너비이고 44px 높이인가?

#### 접근성
- [ ] 포커스 인디케이터(2px 아웃라인, Vibrant Blue)가 보이는가?
- [ ] 텍스트 대비가 최소 4.5:1를 만족하는가?
- [ ] 상태 뱃지가 색상 + 텍스트로 표시되는가?

#### 모션
- [ ] 애니메이션이 prefers-reduced-motion을 준수하는가?

#### 사용성
- [ ] 페이지 간 이동이 직관적인가?
- [ ] 빈 목록에서 다음 행동이 명확한가?

#### 제약 준수
- [ ] 명세 범위 내 기능만 설계되었는가? (파일 첨부 X, 댓글 X)
- [ ] MVP 원칙(단순성)을 따르는가?

### 재심의 기준 (Revision)

**다음 중 하나라도 만족하지 않으면 재디자인 요청**:
1. 색상이 요청 팔레트를 따르지 않음
2. 메인 페이지가 오로라 그라데이션을 포함하지 않음
3. 모바일에서 핵심 시나리오 완료 불가능
4. 포커스 인디케이터 미표시
5. 상태 뱃지가 색상만으로 구분됨 (텍스트 없음)
6. prefers-reduced-motion 미지원
7. 입력 필드 높이 < 44px

### 승인 기준 (Approve)

**다음을 모두 만족하면 승인**:
1. 위 체크리스트의 95% 이상 충족
2. 재심의 기준의 모든 항목 통과
3. 모든 기기에서 반응형 동작
4. 접근성 기준 충족
5. 명세 범위 내 기능만 포함
